Bubble Export Sanitizer

Strip API keys, credentials and personal data from a .bubble app export — in your browser, offline.

No network · nothing stored
Why? Share an export instead of connecting an AI to your app
  • Faster and cheaper on big apps. Through the Bubble MCP, an AI reads your app one request at a time: list the pages, open a page, open each workflow, open each data type… On a large app that is hundreds of calls, and every answer is added to the conversation, so you pay in time and in tokens. A .bubble export is the whole app in one file: the AI (or a script it writes) can search it in seconds and only read the parts it needs.
  • Read-only by design. A file cannot change your app. No editor access, no API keys and no connection to your account are handed to the AI or to the person helping you.
  • A fixed snapshot. Everyone works on the same version: you can attach it to an issue, send it to a contractor or another AI, and compare it with a later export.
  • Safe to share once sanitized. A raw export carries every API key, password and test record in the app. This page removes them first, so the file can go to people and AIs you don't fully control.
How to verify this page is safe
  1. Open your browser's DevTools → Network tab, then load and sanitize a file. The only requests you will see are this HTML and its script, loaded before you picked a file. Nothing is sent afterwards.
  2. The page ships a Content-Security-Policy with connect-src 'none' and default-src 'none': the browser itself refuses any network call, even if the code tried.
  3. Switch your machine to airplane mode and repeat — it works exactly the same.
  4. Nothing is written to localStorage, cookies or IndexedDB. Click Clear memory or close the tab and the file is gone.
  5. Read the source: it is one small file, src/sanitizer.js, plus this page. No build step, no dependencies.
What it does and does not do
  • Only string values are rewritten. Keys, numbers, booleans, nulls, ordering and structure stay identical, so the file keeps its shape and internal references.
  • Bubble ids (1700000000000x100000000000000001, bQZPk, plugin element ids, API call ids), dates and colors are protected and never redacted.
  • Each secret is replaced by [REDACTED:rule:xxxxxxxxxx]. The suffix is a salted, non-reversible hash so the same secret maps to the same placeholder within one run and cross-references still line up. The salt is random per run, so placeholders can't be compared between runs or files.
  • A second pass runs over the output and must find nothing. If it does, the result is flagged and you should not publish the file.
  • It cannot know your business: names of people inside text, addresses, internal URLs or anything that is secret only to you will not be detected. Read the review list and skim the output before publishing.
